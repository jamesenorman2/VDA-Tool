# VDA Tool – standing rules

These come from the project owner and apply to every change.

- **Version number.** `src/version.js` is the single source and must match `package.json` (a test checks it). It is shown at the top of every page and in every copied output. Bump it on every change merged to main: minor for features, patch for fixes.
- **Always merge to main.** Work on the session branch, open a pull request, and merge it to `main` when tests pass. The owner has given standing permission for this.
- **Hosting is Vercel.** Project `vda-tool` (team jamesenorman2's projects) is linked to this repo: every push makes a preview deployment and `main` deploys to production at https://vda-tool.vercel.app. It is a static site; the only build step (`vercel.json`) runs `scripts/write-config.mjs`, which writes `config.js` from Vercel environment variables (`MAPTILER_KEY`). Never commit a real key; the committed `config.js` has an empty one. After merging, check the production deployment is READY.
- **Outputs must be copyable into a report.** Every results table has a copy button that puts an HTML table (pastes into Word) and tab-separated text on the clipboard, with a source line naming the tool version. Charts and sketches copy as PNG on white. Copied content is always light-styled, whatever the page theme.
- **Dark mode is an option and on by default.** Every page sets `data-theme` from `localStorage['vda-theme']` (default `dark`) in an inline head script and has a toggle. Colours come from CSS tokens; print is always light.
- **Entry order is always start of route → asset.** There is no setting for it.
- **Start conditions:** standing (from rest), entry speed (km/h, capped at top speed) or rolling (already at top speed). Explain them in the UI; the calculator shows all three side by side.
- **Report.** `src/report.js` builds the report once as a list of blocks and renders it to HTML (printed to PDF) and Word; add content as blocks so both stay identical. Barrier ratings are given to ISO 22343-1 using the owner-confirmed class mapping (car M1, pick-up N1G, flatbed N1, 7.5 t N2A, 18 t N3F, 30 t N3G; `ISO_CLASS` in `src/summary.js`). PAS 68, IWA 14-1 and ASTM F2656 equivalents are not mapped; don't add them without the owner's confirmation. The Word file uses the owner's house template when one is loaded on the report page (kept in the browser only, never committed – the repo is public); only its page formatting, headers, footers and styles are used, not its front page or contents page. Without a template it uses a default layout.
- **Standards.** Reference notes on ISO 22343 Parts 1 and 2 are in `docs/standards/iso-22343-notes.md`. Test speeds must respect ISO 22343-1 Table 5 (trucks up to 80 km/h, flatbeds up to 96 km/h, cars and pick-ups up to 112 km/h). Never commit the text of a standard (they are licensed to the owner only); write notes in our own words with clause references.
- Run `npm test` before every commit. Do not put model identifiers in commits or code.
